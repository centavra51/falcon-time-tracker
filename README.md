# Falcon Time Tracker

Демо-приложение учёта рабочего времени для тестового задания Falcon: сотрудники, задачи, таймеры, отчёты и CSV.

**Демо:** https://falcon-time-tracker.vercel.app/

**API / Swagger:** https://falcon-time-tracker.vercel.app/docs

**Репозиторий:** https://github.com/centavra51/falcon-time-tracker

[![Integration tests](https://github.com/centavra51/falcon-time-tracker/actions/workflows/tests.yml/badge.svg)](https://github.com/centavra51/falcon-time-tracker/actions/workflows/tests.yml)

## 1. Возможности и архитектура

- Python 3.11–3.13, FastAPI, Pydantic, HTML + Vanilla JavaScript + Tailwind CSS.
- SQLite в режиме WAL при локальном запуске; PostgreSQL через `DATABASE_URL` для Vercel.
- Создание сотрудников с должностью и отделом, проверка повторяющихся имён без учёта регистра, включая кириллицу.
- Один активный таймер на сотрудника. Частичный уникальный индекс защищает от параллельных стартов; API возвращает HTTP 409.
- Атомарная остановка: при одновременных запросах только один сохраняет результат, остальные получают HTTP 409.
- UTC-штампы и живой счётчик, который восстанавливается после обновления страницы.
- Отчёт по периоду, сотруднику и отделу. Границы дат включают `00:00:00Z` и `23:59:59Z`. В выборку попадают записи по времени начала задачи; длительность не обрезается по границам периода.
- Пустой период возвращает нули и пустой журнал, сохраняя сотрудников в сводке.
- CSV: подробный журнал и сводка, UTF-8 BOM для Excel, предварительный просмотр.
- В интерфейсе есть кнопки проверки повторного старта и пустого отчёта.

Данные сохраняются на сервере. При недоступном API интерфейс показывает ошибку подключения. Первое включение создаёт четыре вымышленных сотрудника и примеры задач; `SEED_DEMO=0` отключает заполнение.

Это открытое демонстрационное приложение без авторизации: посетители видят и могут дополнять общий набор данных. Используйте вымышленные имена и задачи. Подключение авторизации и разграничение доступа потребуются для реального учёта рабочего времени.

## 2. Запуск

### Локально

```bash
git clone https://github.com/centavra51/falcon-time-tracker.git
cd falcon-time-tracker
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m unittest -v
uvicorn app:app --reload
```

macOS / Linux:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest -v
uvicorn app:app --reload
```

Интерфейс: http://127.0.0.1:8000/ — Swagger: http://127.0.0.1:8000/docs — проверка API: http://127.0.0.1:8000/api/health.

Локальная база создаётся автоматически в `time_tracker.db`. Путь можно изменить через `TIME_TRACKER_DB`.

### Docker

```bash
docker build -t falcon-time-tracker .
docker run --rm -p 8000:8000 -e TIME_TRACKER_DB=/data/time_tracker.db -v falcon-tracker-data:/data falcon-time-tracker
```

Том `/data` хранит SQLite, а исходники остаются в `/app`.

### Vercel

Зависимости для Vercel явно перечислены в `pyproject.toml`: при его наличии сборщик использует этот манифест. `requirements.txt` содержит те же проверенные версии для локального запуска.

1. Импортировать этот GitHub-репозиторий в Vercel; Framework Preset: **FastAPI**, Root Directory: корень репозитория.
2. Подключить отдельную PostgreSQL-базу, например Neon через Vercel Storage / Marketplace.
3. Добавить секрет `DATABASE_URL` в переменные окружения проекта. Интеграция может добавить его автоматически. Строка подключения должна использовать TLS (`sslmode=require`).
4. Выполнить Deploy / Redeploy. Схема, индексы и вымышленные данные создаются автоматически; инициализация PostgreSQL защищена транзакционной advisory-блокировкой.
5. Открыть корневую страницу, `/api/health` и `/docs`, проверить создание сотрудника и старт/стоп таймера.

На Vercel намеренно запрещён запуск без `DATABASE_URL`: локальный SQLite-файл не обеспечивает постоянного общего хранилища в serverless-функциях. Подробности: [FastAPI on Vercel](https://vercel.com/docs/frameworks/backend/fastapi), [SQLite limitations](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel).

`.env.example` показывает имена параметров. Приложение читает переменные окружения; для локальной загрузки файла можно использовать `uvicorn app:app --reload --env-file .env`. Секреты и базы исключены из Git.

## 3. Использование ИИ

Исходный архив приложения создан автором с помощью **Google Gemini**. Автор назвал использованную среду «Gemini Argon»; точный идентификатор модели и исходная история запросов в архив не включены.

**OpenAI Codex** использован для проверки архива, адаптации хранения к Vercel, исправления ошибок, расширения тестов и подготовки публикации. ИИ помогал писать и проверять код; поведение подтверждается исполняемыми тестами и проверкой приложения.

Ниже — воспроизводимые примеры запросов для этого проекта, а не дословные цитаты из отсутствующей истории Gemini:

> Создай приложение учёта рабочего времени на FastAPI и SQLite: сотрудники с отделами, старт и остановка задач, отчёт по периоду и CSV. Не допускай второй активный таймер у одного сотрудника. Сделай адаптивный интерфейс и интеграционные тесты.

> Проверь фильтры дат на записях в 00:00:00 и 23:59:59 последнего дня. Добавь проверки кириллицы, пустого периода и одновременных запросов старта и остановки.

> Подготовь этот FastAPI-проект к Vercel с постоянной внешней базой. Сохрани SQLite для локального запуска, исключи секреты из репозитория и добавь CI для обеих баз.

## 4. Найденные и исправленные проблемы

Ниже перечислены проблемы, обнаруженные в предоставленном архиве при подготовке публикации. История промежуточных версий Gemini отсутствует, поэтому уже имевшиеся защиты не выдаются за заново найденные ошибки.

| Проблема в архиве | Исправление | Как проверить |
| --- | --- | --- |
| Локальный SQLite не подходит для постоянного хранения на Vercel | Добавлен PostgreSQL через `DATABASE_URL`, SQLite сохранён локально | CI PostgreSQL и сохранение записи после обновления демо |
| При сбое API интерфейс автоматически переходил на браузерное хранилище и выглядел рабочим | Все операции идут через настоящий API; сбой явно отображается | Остановить сервер или заблокировать `/api/health` |
| README приписывал работу Claude и Cursor, хотя автор использовал Gemini | Указан реальный источник архива и отдельно работа Codex; примеры промптов помечены как воспроизводимые | Раздел 3 |
| Docker-команда монтировала пустую папку поверх `/app`, скрывая исходники | База вынесена в отдельный том `/data` | Команда Docker выше |
| Два одновременных запроса остановки могли оба успешно изменить один таймер | UPDATE выполняется только при `ended_at IS NULL`, проверяется число обновлённых строк | `test_11_concurrent_timer_stop` |
| Кнопка проверки повторного старта объявляла любую ошибку подтверждением защиты | Успех проверки показывается только при реальном HTTP 409; пустой отчёт проверяет фактические нули | Кнопки граничных сценариев в интерфейсе |
| Проверка дубликата имени была только перед INSERT, без защиты от параллельного создания вариантов регистра | Уникальный индекс нормализованного имени и обработка конфликта | Параллельное создание сотрудников / HTTP 409 |

Изначально в архиве уже были `UNICODE_LOWER` для кириллицы, включительные границы дат и уникальный индекс активного таймера. Регрессионные тесты проверяют эти свойства. SQLite использует Python `casefold`, PostgreSQL — Unicode `LOWER`; для кириллицы поведение проверяется тестом, для отдельных других письменностей правила могут различаться.

## 5. Проверки

```bash
python -m unittest test_app.py -v
```

12 интеграционных тестов прошли локально на SQLite и в [GitHub Actions на SQLite и PostgreSQL](https://github.com/centavra51/falcon-time-tracker/actions/runs/40705408940).

Набор проверяет создание сотрудников, старт/стоп, повторный старт, пустой период, сохранение при новом клиенте приложения, отделы, оба CSV-режима, кириллицу, точные границы дат, одновременный старт/стоп и некорректные запросы.

GitHub Actions запускает тот же набор на SQLite и отдельном PostgreSQL 17. Для локальной проверки PostgreSQL задайте **TEST_DATABASE_URL** на отдельную тестовую базу. Внимание: тестовый режим очищает таблицы `time_entries` и `employees` в этой базе перед каждым тестом; не указывайте базу демо или рабочие данные.

Ручной сценарий для просмотра:

1. Добавить вымышленного сотрудника, выбрать его и начать задачу.
2. Обновить страницу: активный таймер должен продолжить отсчёт.
3. Нажать проверку повторного старта: ожидается HTTP 409.
4. Остановить таймер и увидеть сохранённую запись в отчёте.
5. Проверить пустой период и вернуться к текущим датам.
6. Отфильтровать по сотруднику/отделу, скачать оба CSV.
7. Открыть демо в другом браузере: серверные записи должны быть общими.

Минимальная длительность мгновенно остановленной задачи — 1 секунда (правило исходного демо). Запись датируется UTC. Внешний Tailwind CDN нужен для оформления интерфейса.
